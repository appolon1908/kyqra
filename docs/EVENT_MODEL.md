# Event model

Kyqra emits version `1.0` events: `crawler.job.accepted`, `crawler.job.started`, `crawler.job.progress`, `crawler.result.created`, `crawler.result.updated`, `crawler.result.duplicate`, `crawler.job.completed`, `crawler.job.failed`, `crawler.job.cancelled`, `crawler.callback.failed`, `crawler.worker.degraded`, and `crawler.worker.recovered`.

The envelope contains `event_id`, `event_type`, `event_version`, `timestamp` (plus middleware-compatible `occurred_at`), `correlation_id`, nullable `causation_id`, `tenant_id`, nullable `customer_id`, nullable `job_id`, `request_id`, `source_service`, `source_node`, `idempotency_key`, `payload`, and `metadata`. IDs are UUIDs at creation boundaries. Correlation IDs are accepted from `X-Correlation-Id` or generated by API intake and copied into queue payloads, jobs, results, events, delivery logs, and audits.

Result payloads use the normalized contract in the mission. Raw field evidence is retained under `provenance`; conflicts are never silently merged. Tenant-local canonical key and payload fingerprint classification produces `new`, `updated`, or `duplicate`; ambiguous future matching must use `conflict` and retain both values. Middleware owns final CRM entity resolution.

The middleware-to-n8n contract is the same envelope. Middleware may route the recommended job/result/failure types, and Kyqra contains no workflow IDs or n8n URLs.
